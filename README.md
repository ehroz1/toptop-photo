# PhotoSeek — универсальный поиск фото

Один поиск сразу по **Pixabay**, **Pexels**, **Unsplash**, **Wikimedia Commons**,
**Openverse**, **Pexafy** и (опционально) **Flickr** и **Shutterstock** + быстрые кнопки для **Яндекс.Картинок**,
**Google Картинок**, **Pinterest** и **Cosmos**. Сам сайт — обычная веб-страница
без установки чего-либо и без сборки; единственный сервер во всём проекте —
маленький Cloudflare Worker, который прячет API-ключи (см. ниже).

## Как запустить

**Шаг 1 — разово настройте прокси для ключей.** Pixabay/Pexels/Unsplash/Flickr
требуют ключи, а ключи не должны лежать в браузере или в репозитории — поэтому
они живут в Cloudflare Worker. Разверните его по инструкции в
[`cloudflare-worker/README.md`](cloudflare-worker/README.md) (5–10 минут,
бесплатно) и впишите адрес воркера в `js/config.js`, поле `WORKER_BASE_URL`.
Без этого шага сайт всё равно откроется, но найдёт фото только через
Wikimedia Commons и Openverse — им ключ не нужен.

**Шаг 2 — откройте сайт.** Проще всего — просто открыть `index.html` двойным
кликом в любом браузере (Chrome, Edge, Firefox, Safari).

Если браузер вдруг заблокирует запросы при открытии файла напрямую (редко, но
бывает в некоторых настройках Chrome), запустите локальный сервер из папки
проекта:

```bash
# любой из вариантов
npx serve .
# или
python3 -m http.server 8080
```

и откройте адрес, который покажет команда (например `http://localhost:8080`).

## Как выложить онлайн (GitHub Pages)

1. Зайдите в репозиторий на GitHub → **Settings → Pages**.
2. В разделе "Build and deployment" выберите источник **Deploy from a branch**,
   ветку — ту, в которую запушен код, папку — `/ (root)`.
3. Через минуту-две GitHub покажет ссылку вида
   `https://<ваш-логин>.github.io/toptop-photo/` — это и есть ваш личный
   поисковик, доступный с телефона и любого компьютера.
4. Убедитесь, что в настройках Cloudflare Worker (`ALLOWED_ORIGINS`) указан
   именно этот адрес — иначе воркер будет отклонять запросы с сайта как
   "origin not allowed".

## Что умеет

- **Русский и английский интерфейс** — язык определяется автоматически по
  языку браузера (`navigator.language`), переключателя в интерфейсе нет
  специально. Если у пользователя браузер на русском — весь интерфейс на
  русском, на любом другом языке — на английском. Логика в
  [`js/i18n.js`](js/i18n.js).
- **Поиск сразу в нескольких источниках** — Pixabay, Pexels, Unsplash,
  Wikimedia Commons, Openverse и Flickr. Результаты перемешиваются в одну
  ленту, каждую карточку можно скачать одним кликом.
- **Отключение источников** — нажмите на чип источника, чтобы временно
  исключить его из поиска. Источники без настроенного ключа (сейчас —
  Flickr) просто не показываются в списке чипов.
- **Яндекс.Картинки / Google Картинки / Pinterest** — кнопки открывают эти
  сервисы в новой вкладке с уже введённым запросом (см. пояснение ниже, почему
  не "в общей ленте").
- **Автоперевод запроса на английский** — если вы вводите запрос по-русски,
  он автоматически переводится на английский перед отправкой в Pixabay/
  Pexels/Unsplash/Wikimedia/Openverse/Flickr (бесплатный переводчик MyMemory,
  без ключа) — так находится заметно больше и точнее, так как большинство
  фото на этих стоках подписаны по-английски. Под строкой поиска появляется
  подсказка "Ищем как: …" со ссылкой "искать как есть", если хотите вернуть
  оригинальный запрос. Яндекс/Google/Pinterest всегда открываются с
  оригинальным (не переведённым) текстом.
- **Понятная плашка лицензии** — в полноэкранном просмотре под описанием
  показывается тип лицензии фото (например, "CC BY-SA", "Pixabay License",
  "CC0") со ссылкой на её текст, а также явные пометки "Можно для коммерции"/
  "Только некоммерческое" и "Нужна атрибуция", если это применимо — чтобы
  сразу было понятно, как можно использовать фото, без похода на сайт
  источника.
- **Отдельный поиск иконок** — переключатель "Фото / Иконки" рядом с
  источниками. В режиме "Иконки" PhotoSeek ищет не фото, а векторные иконки
  через [Iconify](https://iconify.design/) — бесплатный публичный API без
  ключа, объединяющий ~200 открытых наборов (Material Design Icons, Tabler,
  Font Awesome Free и другие, суммарно больше 200 000 иконок). У каждой
  иконки — своя плашка лицензии набора (обычно MIT/Apache/CC0 — открытое ПО,
  не Creative Commons, как у фото), выбор цвета для предпросмотра, копирование
  SVG-кода или идентификатора иконки, а также скачивание в SVG или PNG
  (512×512). Фильтры по ориентации/качеству/цвету/людям и избранное к
  иконкам не относятся и в этом режиме скрыты — это самостоятельный, более
  простой инструмент, а не ещё один "источник" в общей ленте фото.
- **Фильтры** — качество (от 2K/4K/8K по пикселям), ориентация (гориз./верт./квадрат),
  сортировка (популярное/новое), **цвет** (палитра, работает там, где API это
  поддерживает) и **люди/без людей** (эвристика по тегам и описанию — ни один
  из подключённых API не даёт точного распознавания людей на фото, поэтому
  результат приблизительный). Все выбранные фильтры и включённые источники
  запоминаются в браузере и восстанавливаются при следующем визите.
- **Избранное** — сердечко на карточке или в просмотре сохраняет фото в
  личную коллекцию (кнопка с сердечком в шапке сайта). Хранится в этом
  браузере, никуда не отправляется.
- **Выбор нескольких фото и скачивание архивом** — кнопка с галочкой в шапке
  включает режим выбора: отмечайте нужные фото и скачайте их одним zip-файлом.
- **Просмотр фото** — клик по карточке открывает полноэкранный просмотр с
  тегами, описанием, автором, ссылкой на источник, копированием ссылки,
  копированием самой картинки в буфер обмена (чтобы сразу вставить, например,
  в чат или документ через Ctrl+V), кнопкой "Поделиться" (на телефоне
  открывает системное меню шаринга) и скачиванием оригинала. Листать можно
  стрелками ← → на клавиатуре.
- **Горячие клавиши** — `/` — перейти в строку поиска из любого места
  страницы, `Esc` — очистить поле поиска (или закрыть просмотр фото),
  `D` — скачать открытое в просмотре фото.
- **Голосовой поиск** — иконка микрофона в строке поиска (если браузер
  поддерживает распознавание речи — например, Chrome). Сказали запрос —
  он сам подставился и запустил поиск.
- **Операторы поиска** — `-слово` исключает фото с этим словом в теге/
  описании, `"точная фраза"` требует именно такую фразу, `слово1 ИЛИ слово2`
  находит фото хотя бы с одним из них. Подсказка есть при наведении на
  строку поиска.
- **Синонимы** — небольшой встроенный словарь: "кот" сам подтягивает
  "кошка"/"котёнок"/"котик" и т.п., чтобы запрос был шире. В отличие от
  явного "ИЛИ", синонимы не исключают фото жёстко — они просто расширяют
  сам запрос к стокам, поэтому не режут результаты, которых нет в словаре.
- **Исправление опечаток** — бесплатный Яндекс.Спеллер подсказывает "Возможно,
  вы имели в виду…" для обычных запросов (не работает вместе с операторами
  выше).
- **Удаление дублей** — если одно и то же фото случайно нашлось на двух
  разных стоках, PhotoSeek сравнивает превью по отпечатку изображения
  (perceptual hash) и показывает только одну копию.
- **История поиска** — последние запросы — кликабельными чипами на пустом
  экране.
- **Постоянная подгрузка (infinite scroll)** — лента подгружается сама при
  прокрутке вниз, кнопка "Показать ещё" остаётся как запасной вариант.
- **Ссылка на конкретный поиск** — адрес страницы обновляется на
  `?q=ваш+запрос`, так что можно просто скопировать ссылку из адресной
  строки и скинуть кому-то — у него сразу откроется этот же поиск.
- **Светлая/тёмная тема** — кнопка в правом верхнем углу переключает по
  кругу: авто → светлая → тёмная → снова авто. В режиме "авто" тема живо
  следует за системной, даже "на лету" при переключении дня/ночи в ОС;
  ручной выбор запоминается в браузере до следующего клика на "авто".
- **Личная статистика и лимиты** — иконка с графиком в шапке показывает,
  сколько фото скачано, какой источник используется чаще всего и сколько
  осталось из часового лимита Unsplash — не занимает места на экране, пока
  не открыта.
- **Устанавливается как приложение (PWA)** — см. раздел ниже.

### Мелочи для мобильных и не только

- **Свайпы** влево/вправо в полноэкранном просмотре — как в галерее телефона.
- **Вибрация** при лайке, свайпе и успешном скачивании (только на устройствах,
  которые это поддерживают).
- **Перетаскивание фото** прямо с карточки в другое окно/на рабочий стол
  (в Chrome/Edge перетаскивается сразу оригинал, не превью).
- **Предзагрузка** соседних фото в полноэкранном просмотре — переключение
  между фото ощущается мгновенным.

## Почему Яндекс, Google, Pinterest и Cosmos — это кнопки, а не общая лента

У Pixabay/Pexels/Unsplash есть бесплатные публичные API — по ним можно
получать фото напрямую и показывать их в общей сетке. У Яндекс.Картинок и
Google Картинок бесплатного публичного API для поиска изображений нет:

- **Google** предлагает Custom Search JSON API, но он платный после 100
  запросов в день и требует создания отдельного "Search Engine" (нужен API key
  + Search Engine ID).
- **Яндекс** предлагает похожий платный API с похожими ограничениями.
- **Pinterest** вообще не даёт стороннему приложению искать по всему
  Pinterest: его официальный API умеет искать только пины в вашем
  собственном аккаунте (после входа и авторизации через OAuth). Открытого
  поиска "по всему Pinterest" для разработчиков нет — только платные сервисы
  на основе скрейпинга (обход условий использования Pinterest), их
  сознательно не подключал.
- **Cosmos** (cosmos.so) — площадка для сохранённых подборок/референсов,
  официального публичного API вообще не публикует. Есть только неофициальная
  платная обёртка стороннего сервиса (Parse.bot) — тоже сознательно не
  подключал.

Формат ссылки на поиск по Cosmos подтверждён вручную:
`cosmos.so/search/elements/<запрос>%20`.

Поэтому сейчас кнопки просто открывают нужный сервис в новой вкладке с вашим
запросом — быстро и без плясок с регистрацией. Если позже заведёте платный
ключ Google Custom Search или Яндекса — пришлите его, и я добавлю их
результаты прямо в общую сетку.

(Раньше в качестве замены рассматривался **Bing Image Search API**, но
Microsoft полностью закрыла все Bing Search API 11 августа 2025 года —
старые ключи возвращают ошибку, новые выдать нельзя. Поэтому такого варианта
больше нет.)

## Ограничения фильтров "Цвет" и "Люди"

Ни у одного из подключённых фотостоков нет идеального решения для этих двух
фильтров, поэтому здесь всё "лучшее из возможного", а не точная наука:

- **Цвет** реально поддерживают только Pixabay, Pexels, Unsplash, Shutterstock
  и Pexafy — и у каждого свой набор цветов (например, у Unsplash нет серого и
  коричневого, у Pexels нет чёрно-белого; у Shutterstock/Pexafy цвет "ч/б"
  тоже не поддержан — под капотом это поиск по ближайшему hex, а не настоящий
  фильтр монохромности). Wikimedia Commons, Openverse и Flickr фильтр по
  цвету просто игнорируют — по этим источникам вернутся любые цвета.
- **Люди/без людей** ни один из API не различает "по-настоящему" — это
  эвристика: PhotoSeek проверяет теги, описание и название фото на слова
  вроде "person", "man", "woman", "portrait" (и их русские аналоги). Иногда
  фото с человеком на фоне без соответствующего тега проскочит в "Без людей",
  и наоборот — это ожидаемая погрешность подхода, а не баг.
- **Удаление дублей** тоже приблизительное: сравнение идёт по общей яркостной
  "форме" картинки (быстрый и лёгкий метод, работает прямо в браузере без
  сервера), а не по смыслу содержимого. На настоящих фото это работает
  надёжно (одно и то же фото с разных стоков почти всегда даёт совпадение),
  но на абстрактных однотонных картинках метод менее точен.

## Установка как приложение (PWA)

Если сайт открыт по `https://` (например, через GitHub Pages) или на
`localhost`, браузер предложит установить PhotoSeek как приложение:

- **На телефоне (Android/Chrome)** — придёт баннер "Добавить на главный
  экран", либо через меню браузера (⋮) → "Установить приложение".
- **На iPhone (Safari)** — кнопка "Поделиться" → "На экран «Домой»".
- **На компьютере (Chrome/Edge)** — иконка "Установить" появится справа в
  адресной строке.

После установки PhotoSeek открывается отдельным окном без адресной строки
браузера, со своей иконкой на рабочем столе/главном экране, и сама страница
(HTML/CSS/JS) загружается мгновенно даже без интернета — правда, сам поиск
фото всё равно требует подключения к сети, офлайн работает только оболочка
приложения.

## Про Flickr

Раньше Flickr выдавал бесплатный "Non-Commercial" API-ключ любому желающему.
Сейчас, чтобы вообще подать заявку на ключ, нужна платная подписка
**Flickr Pro** — бесплатного пути больше нет. Поэтому чип "Flickr" в
интерфейсе сейчас скрыт (код-то есть, включать нечем).

Если когда-нибудь оформите Flickr Pro и получите ключ — добавьте его как
секрет `FLICKR_API_KEY` в Cloudflare Worker (см.
[`cloudflare-worker/README.md`](cloudflare-worker/README.md)) и поставьте
`FLICKR_ENABLED: true` в [`js/config.js`](js/config.js) — чип появится сам,
без других изменений в коде.

## Про Shutterstock

Shutterstock — единственный источник в общей ленте, у которого фото **не в
свободной лицензии**. Бесплатный ("Discovery") доступ к Content Search API
даёт только поиск и превью со знаком Shutterstock — ни превью, ни то, что
скачивает кнопка "Скачать", не является лицензированным файлом, это одна и
та же водяная картинка. Полноразмерный файл без знака доступен только после
покупки лицензии на сайте Shutterstock (ссылка на карточку товара — в плашке
лицензии в просмотре фото, там же явная пометка "Нужна платная лицензия").
Добавьте свой Personal Access Token как секрет `SHUTTERSTOCK_TOKEN` в
Cloudflare Worker (создаётся в личном кабинете на
[shutterstock.com/developers/apps](https://www.shutterstock.com/developers/apps),
раздел API Access — не нужен отдельный OAuth-обмен client_id/secret) — чип
"Shutterstock" работает сразу, без изменений в `js/config.js`.

## Про Pexafy

Pexafy — отдельный агрегатор, который сам одним запросом ищет сразу по девяти
бесплатным фотостокам (Unsplash, Pexels, Pixabay, Kaboompics, Burst,
StockSnap, Picjumbo, Skitterphoto, NegativeSpace) с семантическим поиском по
смыслу описания, а не только по ключевым словам, и заявляет весь свой каталог
как free-to-use без обязательной атрибуции. У Pexafy также есть отдельный
MCP-сервер (`mcp.pexafy.com`) для AI-ассистентов вроде Claude — это другой
протокол для другого сценария (агент ищет фото прямо в диалоге), к нашему
статическому сайту он не подключается; здесь используется только их обычный
REST API (`api.pexafy.com`, заголовок `x-api-key`).

Получите ключ на
[pexafy.com/dashboard/api-keys/create](https://pexafy.com/dashboard/api-keys/create/)
— выберите тип **Pexafy API** (не **MCP**, это ключ для другого протокола) —
и добавьте его как секрет `PEXAFY_API_KEY` в Cloudflare Worker. Чип "Pexafy"
заработает сразу, без изменений в `js/config.js`.

## API-ключи и прокси на Cloudflare Worker

Ключи Pixabay, Pexels, Unsplash, Flickr, токен Shutterstock и ключ Pexafy
больше **не хранятся в браузере и не коммитятся в репозиторий** — они лежат только как
секреты отдельного Cloudflare Worker (папка
[`cloudflare-worker/`](cloudflare-worker/)), а сайт обращается к нему уже без
ключей вообще. Настройка воркера — пошагово в
[`cloudflare-worker/README.md`](cloudflare-worker/README.md); после деплоя
нужно вписать его адрес в [`js/config.js`](js/config.js), в поле
`WORKER_BASE_URL`. Wikimedia Commons и Openverse ключей не требуют вовсе — к
ним сайт по-прежнему обращается напрямую.

⚠️ **Старые ключи, которые раньше лежали прямо в `js/config.js`, навсегда
остались в истории git-коммитов** этого публичного репозитория — их можно
найти, даже если текущая версия файла их не содержит. Чтобы это перестало
быть проблемой, зайдите в личный кабинет каждого сервиса и перевыпустите
(regenerate) ключ, а новый впишите только в секреты воркера — подробности в
`cloudflare-worker/README.md`.

Практические следствия:

- Если какой-то источник перестал отвечать — сначала проверьте предупреждение
  в интерфейсе (там текст ошибки прямо от воркера) и настройки секретов
  воркера в панели Cloudflare.
- У Unsplash демо-ключи имеют лимит **50 запросов в час** — при активном
  использовании он может закончиться быстрее, чем у Pixabay/Pexels. Это не
  баг: просто подождите час, либо получите свои **5000 запросов/час бесплатно**
  легальным путём — подайте заявку на статус "Production" в личном кабинете
  на unsplash.com/oauth/applications (кнопка "Request Approval", скриншоты
  приложения с корректной атрибуцией автора — их проверка занимает около
  5 рабочих дней).
  ⚠️ Заводить несколько ключей на аккаунтах друзей ради обхода лимита
  не стоит — API Terms Unsplash прямо запрещают использовать несколько
  приложений/аккаунтов для обхода квоты, и это может привести к блокировке
  как ваших ключей, так и ключей друзей. Легальный путь выше даёт лимит
  в 100 раз больше и без этого риска.
- У Openverse без регистрации тоже есть лимит на анонимные запросы (около
  100 в день с одного IP). Для личного использования обычно достаточно; если
  начнёт не хватать — на api.openverse.org можно бесплатно зарегистрировать
  приложение и получить более высокий лимит (Openverse не требует прокси —
  можно просто прописать ключ прямо в `js/providers.js`, у него нет
  требования конфиденциальности как у Unsplash).

### Соответствие Unsplash API Guidelines

Все пункты официальных правил теперь выполнены:
- Показываем фото только через прямые ссылки `photo.urls`, ничего не
  перезаливаем на свой сервер.
- При любом действии, похожем на скачивание (кнопка "Скачать", массовое
  скачивание zip-архивом, копирование картинки в буфер, "Поделиться" файлом,
  перетаскивание фото на рабочий стол) дёргаем `photo.links.download_location`
  через воркер.
- Ссылки на автора и на страницу фото на Unsplash подписаны меткой
  `utm_source`/`utm_medium` (имя приложения — `UNSPLASH_APP_NAME` в
  `js/config.js`, впишите туда точное название вашего приложения с
  unsplash.com/oauth/applications, если оно отличается от `photoseek`).
- В просмотре фото подпись выглядит как официальный пример Unsplash "Photo
  by Annie Spratt on Unsplash" — оба слова, и имя автора, и "Unsplash",
  кликабельны и ведут по правильным ссылкам с utm-меткой.
- Название приложения — "PhotoSeek", иконка своя, а не логотип Unsplash;
  фото не продаются; поиск запускает сам человек, без автоматических
  массовых запросов; есть пауза при 429-й ошибке, чтобы не долбить API.
- **Access Key остаётся секретным** — теперь он живёт только как секрет
  Cloudflare Worker и никогда не попадает в браузер или в репозиторий.

## Структура проекта

```
index.html             — разметка страницы
css/styles.css          — все стили, светлая/тёмная тема, иконки (встроены как SVG)
js/config.js            — адрес воркера и прочие настройки (без ключей)
js/i18n.js              — локализация интерфейса (русский/английский)
js/providers.js         — обращения к API стоков (через воркер) + фильтры по цвету/людям
js/icons.js             — поиск иконок через Iconify (отдельный режим "Иконки")
js/translate.js         — автоперевод запроса на английский (MyMemory API)
js/queryLogic.js        — операторы поиска (-слово/"фраза"/ИЛИ) и синонимы
js/spellcheck.js        — исправление опечаток в запросе (Yandex Speller)
js/dedupe.js            — удаление дублей фото между стоками (perceptual hash)
js/app.js               — вся логика: поиск, фильтры, избранное, лайтбокс,
                           массовое скачивание, горячие клавиши, PWA
manifest.webmanifest    — описание приложения для установки (PWA)
sw.js                   — service worker, кэширует оболочку приложения
icons/                  — иконки приложения (192/512/maskable)
cloudflare-worker/      — прокси-сервер, хранит настоящие API-ключи
                           (worker.js, wrangler.toml, инструкция по деплою)
```

Никаких фреймворков и сборщиков — чистые HTML/CSS/JS, поэтому редактировать
и запускать можно без установки Node.js или чего-либо ещё. Единственная
внешняя библиотека — [JSZip](https://stuk.github.io/jszip/) для массового
скачивания архивом, подключается прямо со CDN (cdnjs.cloudflare.com) в
`index.html`, без установки.
